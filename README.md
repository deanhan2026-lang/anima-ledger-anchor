# 灵元责任账本 · 外部锚定点

**这个仓库只存哈希，不存任何内容。** 目的是把「信任根指纹」和「账本链头」钉在一个
我们**不是唯一所有者**的位置上。

## 为什么需要它

如果验签用的公钥和账本放在同一个可写目录，攻击者只要：

1. 换成自己的公钥
2. 改账本内容
3. 用自己私钥重签全链
4. 重算并覆盖锚定文件

任何只读该目录的校验者都会**全绿通过**。这不是假设——2026-10-22 我们自己复现过，
用的就是我们自己的校验器（含公开的复现脚本）。

所以信任根必须钉在**攻击者不便同时改写的地方**。本仓库就是其中一个钉子。

## 存了什么

| 字段 | 含义 |
|---|---|
| `pubkey_fingerprint_sha256` | 公钥的 32 字节原始公钥的 sha256。**这是真正的信任根** |
| `pubkey_raw_hex` | 同上，十六进制形式，便于人手核对 |
| `ledger_entry_count` | 发布时刻账本条数 |
| `ledger_head_hash` | 最后一条的 `entry_hash` |
| `ledger_file_sha256` | 整份账本文件的 sha256 |
| `all_entry_hashes` | 全部 `entry_hash` 列表，用于对照"我手上这份是不是同一份" |

## 这个仓库能证明什么

- 在 `published_at` 这个时间点，账本有 N 条、链头是 H、公钥指纹是 F
- 若之后有人用**不同**公钥冒充该账本，指纹对不上 → 可发现
- 若之后账本条数**变少** → 有行被删除，可发现

## 这个仓库**不能**证明什么（重要）

1. **不能证明账本内容真实。** 哈希只能证明"没被改动过"，不能证明"记录的事是真的"
2. **不能证明发布之前没被改过。** 本仓库从第一次发布才开始有约束力
3. **不能证明我们不会删这个仓库。** 仓库所有者仍可删库；但删除是**公开可见**的行为，
   且外部验证者若自行留存过副本，删库无法使已流传的证据消失
4. **不能替代外部见证。** 最强的保证来自多个互不隶属的见证方各自留存链头

## 第三方怎么核对

```
F = 你能从账本发布方独立取得的公钥（不要只信本仓库）
  对公钥 32 字节原始形式做 sha256 → 应当等于 pubkey_fingerprint_sha256
  对整份账本文件做 sha256        → 应当等于 ledger_file_sha256
  最后一条的 entry_hash          → 应当等于 ledger_head_hash
```

任一项对不上，就不能声称"已验证"。

## 边界

单节点（nyx-windows, WLMHAN）单日锚点。多节点、多见证方的锚定仍在推进中。
未解问题清单随账本一并发布，见 `OPEN_PROBLEMS.md`（在账本侧，不在本仓库）。
